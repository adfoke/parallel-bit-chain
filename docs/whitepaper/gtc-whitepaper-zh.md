## 摘要

GTC 是一条 Nakamoto 共识的工作量证明（PoW）区块链，复刻 Bitcoin 的账本语义 —— UTXO 模型、600 秒出块、2100 万枚总量与 210,000 块减半、2016 块难度调整 —— 并只替换其中的工作量证明函数。

算法 **Geyser** 的设计目标：让经济上理性的挖矿设备恰好是商品级消费 GPU。每次哈希对 6 GiB epoch 数据集执行 64 轮 128 字节随机访问（每哈希 8 KiB），将吞吐绑定于内存带宽；同时执行一段由上一区块哈希重新生成的 256 条混合整数/IEEE-754 浮点指令程序，将效率绑定于通用执行单元。

本设计**不声称绝对的 ASIC 免疫** —— 任何诚实的设计都不能。取而代之，它对定制芯片施加两个经济约束：压缩效率上限（目标 ≤ ~2×），以及每 2–3 年一次的预定算法轮换，使芯片在回本前失效。同时，消费级 GPU 是全球内存带宽的成本最优点（2026 年约 $0.8–1.1 / GB/s），结构性排除 CPU（每 hash 美元成本差 ~5–60×）、FPGA（~10×）与 AI 数据中心加速器（~5–9×）。统一内存机器（Apple Silicon 一类）零协议改动即可原生挖矿。

验证廉价：全节点仅持有 48 MiB cache，按需重生成被访问的 dataset 项，验证一个区块头约 8 ms CPU。链以零预挖、共识层零开发税、≥ 6 个月公开测试网、前 10,000 块签名 checkpoint 启动。

## 1. 引言

### 1.1 工作负载形状决定硬件类别

SHA-256d 无状态、无内存依赖 —— 这个形状对全定制芯片极度友好。Bitcoin 上线四年内挖矿完成 CPU → GPU → FPGA → ASIC 的迁移，算力集中到少数有晶圆厂背景的制造商寡头手中。单台现代 ASIC 矿机超过家用电脑八个数量级以上；参与挖矿从"下载一个软件"变成了产业供应链问题。

Ethereum 的 Ethash 是迄今最成功的反例：2015–2022 年，其 GB 级 DAG 将挖矿绑定于内存带宽，网络安全由数百万张分散的消费级 GPU 支撑。同期 Ethash ASIC 仅取得 2–3× 效率优势，且被数据集增长自然淘汰（Bitmain E3 死于 4 GB 内存上限）。Kaspa 提供了现代反面教材：轻量的 kHeavyHash 在约 18 个月内被 ASIC 支配。

**论题：抗 ASIC 政策的成败取决于工作负载的*形状*，而非口号。** Geyser 的形状就是商品 GPU 的形状。

### 1.2 立场声明

Geyser 不*阻止* ASIC，而是让 ASIC 成为坏投资：

1. **带宽绑定** —— 证明过程受内存带宽约束；定制芯片必须在与消费 GPU 厂商相同的市场采购商品内存（GDDR/HBM），且批量条款更差；
2. **程序化混合** —— 每块随机生成的 256 条混合整数/浮点指令程序要求通用可编程核心；专用逻辑只能加速工作负载的一小部分；
3. **敏捷契约** —— 共识内建的预定算法轮换，每 2–3 年一次；对 GPU 矿工是软件升级，对 ASIC 是重新流片。

### 1.3 诚实的边界

本文量化而非掩盖本方案的局限：GPU 农场无法被算法设计排除；商品硬件的可转卖性使 51% 攻击成本降为"折旧 + 电费"；网络早期全网算力小于可租用的云机队（§6.3、§10）。

## 2. 链层（Bitcoin 同构）

除工作量证明与扩展头之外的每一处都复刻 Bitcoin。

| 参数 | 值 | 与 Bitcoin 关系 |
|---|---|---|
| 共识 | Nakamoto 最长链 | 相同 |
| 目标出块间隔 | 600 秒 | 相同 |
| 难度调整 | 每 2016 块，BTC 公式，±4× 限幅 | 相同 |
| 初始区块奖励 | 50 GTC | 相同 |
| 减半 | 每 210,000 块（~4 年） | 相同 |
| 总量 | 21,000,000 GTC | 相同 |
| Coinbase 成熟期 | 100 块 | 相同 |
| 区块重量上限 | 4,000,000 WU（SegWit 折扣） | 相同 |
| 账本 | UTXO | 相同 |
| 默认签名 | Schnorr（BIP340），接受 ECDSA | Taproot 语义 |
| 地址 | Bech32m，HRP `gtc` | 格式相同 |
| 脚本 | tapscript v1 白名单（含 CLTV/CSV）；裸 multisig 由密钥聚合（MuSig2 风格）替代；MUL/DIV/CAT 暂缓 | 超集政策 |
| OP_RETURN 载体 | 每笔 1 个输出，≤ 80 字节（策略而非共识） | 相同 |

**区块头：128 字节**（Bitcoin 80 字节的超集）：

```
偏移  长度  字段
0     4    version
4     32   prev_hash
36    32   merkle_root
68    4    timestamp         (BIP113 median-time-past)
72    4    nBits             (紧凑编码 256-bit 目标，同 Bitcoin)
76    8    nonce             (64-bit)
84    2    algo_version      (Geyser 版本，见 §4)
86    32   mix_digest        (PoW 中间态摘要，供轻客户端验证)
118   10   reserved (0)
```

64-bit nonce 消除了 extranonce 回绕；`mix_digest` 对应 Ethash 的 mixHash —— 轻客户端凭 48 MiB cache 即可验证区块头，无需 6 GiB dataset。

**吞吐。** 典型饱和区块 1.5–2 MB：SegWit 典型交易约 12 TPS，Taproot keypath 约 15 TPS。4M WU 上限**有意不提高**：区块增大抬高全节点成本（IBD、带宽、存储），与链的分布性目标直接冲突。更高吞吐属于 Layer 2。

## 3. Geyser 工作量证明

### 3.1 哈希构造

一次哈希 = 32 个并行 lane（一个 CUDA warp / 半个 wavefront / 一个 Apple SIMD-group）× 64 轮。每轮执行一次 dataset 访问（全 lane 共享索引；各 lane 消费不同字）加 4 条程序指令。

```
hash_geyser(header, nonce, program, dataset) -> u256:
    seed = keccak512(header_128B || nonce)
    for lane in 0..32:
        R[lane] = 64 × u32 寄存器   (由 seed 按 lane 派生)
        F[lane] = 64 × f32 寄存器   (R 的位重解释)
    for round in 0..64:
        idx  = index(R[0][0..8], round) mod N_items
        item = dataset[idx]                       # 128 B = 32 × u32
        for lane in 0..32: R[lane][k] = fnv1a(R[lane][k], item[lane])
        execute program[round*4 .. round*4+3]     # 同样 4 条指令,所有 lane
    return keccak256(concat_lane_states(R, F))    # 同时写入 header.mix_digest
```

每哈希 dataset 随机流量：64 × 128 B = **8 KiB**。RTX 5090（1.79 TB/s）理论上限 ~220 Mh/s；预期实现 60–120 Mh/s —— 与 Ethash 时代硬件同数量级，证实带宽（而非逻辑）是绑定约束。

### 3.2 Epoch 数据集（两级结构）

```
epoch_seed(0) = keccak256("GTC/mainnet/genesis-seed-v1")
epoch_seed(e) = keccak256(epoch_seed(e-1))

cache(e)      = gen_cache(epoch_seed(e))     # 48 MiB, Argon2id 风格顺序 KDF
dataset(e)[i] = gen_item(cache(e), i)        # 项间独立,可并行
```

- **矿工**全量持有 dataset（创世 6 GiB，每 epoch +32 MiB）于显存 —— 或统一内存零拷贝，或系统内存（性能惩罚）；
- **全节点/轻客户端**仅持 48 MiB cache，按需重生成每个区块头访问的 ≤ 64 个 dataset 项：约 8 ms CPU。初始块下载（IBD）不需要 dataset；
- Epoch 长度 2016 块（~14 天），与难度窗口对齐。矿工在边界前 1024 块预生成；dataset 经 p2p 网络分发（以太坊验证过的实践）。

### 3.3 程序层

```
program_seed = keccak256(prev_block_hash || epoch_seed)
rng          = xorshift128+(program_seed)
program      = 256 条指令:
               dest  ∈ [8, 64)      # 前 8 个寄存器是 mix 态,禁写
               src1  ∈ [0, 64)
               src2  ∈ [0, 64) 或立即数
               opcode ∈ 指令集
               每 8 条 1 条 FP 指令(固定模式)
最后 32 条: merge —— F 寄存器位重解释后乘法混合回 R
```

**指令集（v1：18 条整数 + 3 条浮点）：**

| 类别 | 指令 |
|---|---|
| 算术 | iadd, isub, imul (u32), imulhi, umin, umax |
| 位运算 | and, or, xor, andnot, shl, shr, rol, ror |
| 位操作 | popcount, clz, bswap, brev |
| 混合 | fnv1a-mul |
| 浮点 | fadd, fmul, fma (IEEE-754 f32, round-to-nearest-even) |

**确定性规则**（浮点是先前算法翻车之处）：

1. 禁止超越函数、除法、开方 —— 跨厂商不保证位一致；
2. FMA *允许*：IEEE-754 将 fma 定义为无限精度乘加后单次舍入，所有合规硬件位一致；
3. Denormal 显式处理：每条 FP 指令后跟 compare-and-select 将次正规结果清零（一条 select，成本可忽略），中和"GPU 清零 / CPU 保留"的平台分歧；
4. P0 发布交叉验证测试向量（NVIDIA / AMD / Intel / Apple GPU / ARM64 CPU，每方 ≥10⁶ 程序-状态对）—— 位级一致是冻结判据。

编译纪律：禁止 `--use_fast_math` / `-ffast-math`；显式设置 `--ftz=false`（算法规则之上的双保险）。

### 3.4 难度

与 Bitcoin 完全一致：`nBits` 紧凑编码 256-bit 目标；`mix_digest ≤ target` 即有效。2016 块重调整与 ±4× 限幅照抄，不作修改。

### 3.5 数据集增长政策（VRAM 政策）

| 项 | 值 |
|---|---|
| 初始 dataset | 6 GiB |
| 增长 | 每 epoch +32 MiB（≈ 0.83 GiB/年） |
| 绑定政策 | dataset ≤ min(中位游戏显卡 VRAM, 中位 UMA 机器内存) 的 60% |
| 复核节奏 | 每两年；可经 `algo_version` 冻结或放缓增长 |

增长持续抬高定制芯片的内存 BOM 下限 —— 这是淘汰 Ethash E3 的同一机制 —— 而 60% 上限保证中位消费显卡可用（今日 6 GiB + 余量适配 8 GB 卡；2030 年预计 ~9.3 GiB 对同期 16–24 GB 中位）。

## 4. 算法敏捷性

`algo_version`（header 偏移 84）选择全部参数集。预定轮换是共识内建的分叉，高度表在创世时固定：

| 版本 | 计划高度 | 变更 |
|---|---|---|
| 0x0001 | 创世 | Geyser v1 冻结 |
| 0x0002 | ~ 第 3 年 | 指令集扩展（+4–6 条），FP 配比调整 |
| 0x0003 | ~ 第 6 年 | 增长政策复核；lane 结构重排 |
| 0xFFxx | 应急 | 规范预置；参数不公开，客户端预发布实现 |

不对称性即防御：GPU 矿工的升级成本是一次软件下载；ASIC 的升级成本是重新流片加 NRE 重付。预定轮换间隔（2–3 年）低于经验上的 ASIC 回本周期（~18–24 个月），即使在最优效率优势下投资也不理性。Monero 2018–2019 年的连续四次成功驱逐 ASIC 是该社会契约的实战先例。

**消费级 GPU 是全球内存带宽的成本最优点。** 将 PoW 绑定于带宽，即把理性挖矿设备锁定在该最优点上。

### 5.2 ASIC 最优情形分析

假设厂商完美实现 Geyser 专用芯片：在与 GPU 厂商相同的 GDDR/HBM 市场采购内存（批量条款更差）；逻辑剥离显示/光追（die 减 ~30%）；自建板级/电源/散热；NRE $10–30M 摊在数万片产量上，对消费 GPU 市场的数千万片。实现的 BOM 优势 ~25–35% —— 大部分被 NRE 摊销与产量劣势吃掉 —— 这还是在轮换日程（§4）摧毁剩余回本空间之前。历史校准点：真实世界 Ethash ASIC 对一个*更弱*的算法（无程序层、无轮换）取得 2–3×。Geyser 的预期上限更低。

## 6. 对抗性分析

### 6.1 AI 数据中心集群

直说：AI 加速器是通用硬件；它们全速执行 Geyser 的程序层，轻松装下 dataset。**架构上没有任何东西拦得住它们；防线纯粹是经济性的。**

- **挖矿**：H100/H200/B200 承担结构性 5–9× 的 $/GB/s 劣势。该差距代际稳定（H100 vs 4090 ≈ 4.7×；B200 vs 5090 ≈ 4.4×），因为 AI 卡与消费卡骑同一代内存技术 —— HBM 溢价是数据中心利润率加先进封装成本，不是暂时性技术差。按 spot 价租用（~$2.5–3.5/时获得 ~5× 5070 吞吐、~50× 时薪成本）每 hash 亏 ~10×；
- **短租 51% 攻击**：对 5 万张消费卡的早期网络，51% 需 ~1 万张 H100 ≈ $30k/时 —— 持续支付每 hash 5–10× 的"AI 溢价"，而防守方只需守住主链。跨供应商扫货 spot 容量会推动公开价格 —— 这本身就是可见的预警信号。攻击成本随诚实算力线性增长；spot 深度不增长；
- **AI 寒冬后的闲置机队**：唯一使 AI 硬件边际成本（只剩电费）低于消费 GPU 的情景。届时威胁是集中度（单实体 >50%），而非挖矿本身。缓解属运营层：池级集中度监测、异常告警、应急 checkpoint 社会协调（§10）。前提是机会成本闸门先失效 —— 历史上 AI 负载时薪是挖矿的 10–20 倍。

**结论：AI 集群是最贵的算力，不是最强的敌人。** 对 ASIC 的防御论点是"它们会太便宜"；对 AI 集群的防御论点是"它们太贵"。两端都被堵上。

### 6.2 统一内存架构（UMA）

Apple Silicon、Strix Halo 级 SoC 及后继者让 CPU/GPU 共享内存。Geyser 绑定的是*内存带宽* —— 一个物理量 —— 而非*独立显存* —— 一种封装选择。推论：

- **共识零改动。** dataset 驻留统一内存，GPU 零拷贝随机访问；UMA 事实上是 dataset 驻留的最优形态；
- **Mac 级机器是合法矿机**：M4 Max（546 GB/s）实现 ~30–40 Mh/s ≈ 0.8× RTX 5070；M3 Ultra 达到 4080 级。LPDDR 能效更高（含整机 ~0.26 vs ~0.42 W / GB/s）—— UMA 上每 hash 能耗*更低*；
- **无新集中化向量**：整机 $/GB/s 仍比独显差 4.5–8×；沉没成本挖矿（已拥有的 Mac 边际成本只有电费）是分布性的*增量*，与闲置游戏 PC 对称；
- **工程成本**：第三个 GPU 后端（Metal）。Apple 的 SIMD-group 也是 32 —— lane 结构不变。§3.3 的 denormal 规则预先中和了 Apple 的 FTZ 默认。测试向量扩至五平台。

若 UMA 成为 PC 主流形态，矿工基数从"装独显的电脑"扩大为"基本上所有现代电脑" —— 更接近中本聪的一人一机原初理想，同时保留 GPU 级带宽经济学。

### 6.3 GPU 侧集中度（诚实台账）

农场无法被算法设计排除。缓解：极端可及性（一张卡即可挖）、Stratum v2（小矿工不经中心化池代理保留建块权）。商品硬件可转卖使攻击成本降为折旧 + 电费 —— 分布性的固有代价；对称地，ASIC 二手残值为零把矿工绑定在其制造商上，本身就是中心化力量。早期网络对云租用的脆弱性在启动机制中处理（§8）。

## 7. 数据锚定（中立政策）

GTC 在共识层内容中立。链上嵌入数据无法被实质审查（witness 签名研磨可嵌入任意比特）—— 因此像 Bitcoin 一样，链把数据需求*引导*至最无害的载体，而非假装阻止：

- **OP_RETURN 政策**：每笔交易 1 个输出、负载 ≤ 80 字节（mempool 策略而非共识 —— 无需分叉即可调整）。80 B 容纳 32 字节摘要 + 协议标识 + 元数据，且与 OpenTimestamps 附件格式字节兼容；
- OP_RETURN 输出不可花费 → **UTXO 零污染**（若无此政策，用户把数据嵌入假 P2PKH 输出，那才污染）；
- **聚合模式**：N 份证据哈希 → Merkle 树 → 根上链。饱和区块承载 60–90 万笔裸锚/天；聚合后上限是费用而非容量；
- **公信力边界，诚实声明**：证据力随锚定链自身公信力而变；新链弱于 Bitcoin。推荐模式是**双锚定** —— 高频锚 GTC（便宜），终局锚 Bitcoin —— 凭 OTS 兼容性零额外设计成本；
- 原始文件永不上链；隐私与内容合规留在链下。GTC 承载哈希而非内容，不承担监管面。

锚定是付费的、UTXO 中性的、与代币投机无关的 —— 在补贴衰减的长期图景中，这是安全预算的可持续费用来源。

## 8. 启动与治理

| 项 | 决定 |
|---|---|
| 预挖 | **零**；无 instamine |
| 开发资金 | 共识中无（无 dev tax）；仅捐赠/基金 |
| 创世 | 公开规范 + 三平台客户端二进制 + ≥ 6 个月公开测试网，之后约定 UTC 时刻启动 |
| 早期防御 | 前 10,000 块签名 checkpoint（官方渠道），杜绝私有链延展 |
| 挖矿协议 | Stratum v2（参考客户端内建）：小矿工保留建块权 |
| 算法治理 | 参数变更 = 预定 `algo_version` 分叉；BIP 式规范流程；多客户端实现制衡 |

## 9. 代币经济

刻意与 Bitcoin 完全一致：创世补贴 50 GTC，每 210,000 块减半，终量 21,000,000 GTC，coinbase 100 块成熟。每天 144 块 → 首年日增发 7,200 GTC。简单性即特性：没有新的发行日程可供争论，一条安全预算曲线，一个费用市场。长期安全由费用需求（交易费 + 锚定需求，§7）对抗递减补贴承载 —— 与 Bitcoin 面对同样的均衡，诚实面对而非重新发明。
