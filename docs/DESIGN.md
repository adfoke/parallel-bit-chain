## 0. TL;DR

GTC（GPU Chain，ticker **GTC**）是一条**尽可能复刻 Bitcoin 语义**（UTXO、10 分钟出块、2100 万枚、四年减半）的 PoW 公链，唯一的核心差异是共识算法：

> **PoW 算法 Geyser 被专门设计成"商品 GPU 形状"的工作负载 —— 以显存带宽为主瓶颈、以随机生成的混合整数/浮点程序为辅瓶颈，使专用矿机（ASIC/FPGA）相对消费级显卡的效率优势被压制在 ~1.5x 以内，再通过算法版本轮换摧毁其投资回收预期。**

一句话：**不是"禁止 ASIC"（技术上不可能），而是让"造 ASIC 不如买显卡"。**

## 1. 背景与动机：为什么"GPU-only"

### 1.1 Bitcoin 的算力集中史

SHA-256d 是一个"纯逻辑、无状态、无内存依赖"的哈希函数。这种形状的 workload 对全定制芯片极度友好：

| 时代 | 硬件 | 时间跨度 |
|---|---|---|
| 2009–2010 | CPU | ~1 年 |
| 2010–2011 | GPU | ~1 年 |
| 2011–2013 | FPGA | ~1.5 年 |
| 2013–今 | ASIC（28nm→3nm） | 终态 |

结果：比特币算力集中在少数几家掌握先进制程与供应链的矿机厂商手中（Bitmain、MicroBT 等），单台矿机算力是家用电脑的 **10^8 倍以上**。普通用户参与挖矿的通道实质关闭。

### 1.2 GPU 挖矿的黄金样本：Ethereum (2015–2022)

Ethash 是至今**最成功的大规模抗 ASIC 算法**：

- 主网 GPU 挖矿存活 **7 年**（2015–2022），峰值全网算力约 1 PH/s，由数百万张分布在全球的消费级显卡构成；
- 期间出现的 Ethash ASIC（Bitmain E3、Linzhi 等）效率优势仅 ~2–3x，且被 DAG 增长在 2 年内自然淘汰（E3 因 4GB 内存上限报废）；
- 显卡来源极度分散：游戏玩家、网吧、家用闲置机、中小矿场，二手市场流动性极强。

### 1.3 反面教材：Kaspa (2021–2023)

kHeavyHash 状态小、混合简单、内存依赖弱，号称 GPU 友好。专用 ASIC 在 **约 18 个月内**（2023）出现并取得数量级优势，GPU 矿工瞬间归零。

**结论：抗 ASIC 的成败取决于算法的"形状"，而不是口号。** 形状三要素：

1. **大工作集**（GB 级数据集，随机访问）→ 瓶颈是内存带宽，而带宽是 ASIC 最难白嫖的资源；
2. **指令多样性 + 每块变化的程序** → 芯片必须实现一个通用可编程处理器，即"重新发明 GPU"；
3. **算法可演进** → 就算前两条被攻破，轮换参数让芯片投资来不及回本。

### 1.4 为什么 GPU ≈ 分布性（以及诚实的反面）

支持论据：

- **商品硬件**：GPU 年出货量数千万张，无单一买家能垄断供给；
- **二手市场**：全球流通、即时定价、可随时退出——算力门槛是"一张显卡"，不是"一集装箱矿机"；
- **后 ETH-merge 时代**：大量闲置 GPU 算力存在，启动期算力来源天然分散；
- **多厂商**：NVIDIA / AMD / Intel 三家竞争，任何算法优化都会同时惠及所有用户。

必须诚实承认的弱点（详见 §7.4）：

- GPU **农场**依然会出现（ETH 时代大农场占比 40%+），GPU 只是比 ASIC **更分散**，不是乌托邦；
- 商品硬件可 resale → 51% 攻击成本 = "折旧 + 电费"，而非全部采购价；
- 消费级 VRAM 容量增长是算法存续的硬约束（见 §6.3 VRAM 政策）。

## 2. 目标与非目标

### 目标

1. **G1 共识**：Nakamoto PoW，最长链规则，与 BTC 同构的安全假设；
2. **G2 矿工准入**：任何一张近十年内发布的、≥8GB 显存的消费级/工作站显卡，以及 ≥16GB 内存的统一内存（UMA）机器（Apple Silicon、Strix Halo 类），都能有竞争力地挖矿；
3. **G3 ASIC 抑制**：把 ASIC 的效率优势（单位电费算力 / 单位资本算力）压制在 **≤ 2x**，并通过轮换机制使其无法回本；
4. **G4 验证廉价**：普通 CPU 全节点验证单个区块头 ≤ 10ms（保证 IBD 与 SPV 可行）；
5. **G5 BTC 兼容语义**：UTXO、脚本模型、地址格式、经济参数对齐 Bitcoin，钱包/工具链可低成本移植。

### 非目标（v1 明确不做）

- 绝对的 ASIC 免疫（**不存在**，任何声称者都在说谎）；
- 智能合约 / 图灵完备脚本（保持 Bitcoin Script 子集）；
- CPU 挖矿友好（与 G2 冲突，RandomX 走的是另一条路）；
- 隐私特性、Layer2、DAG 出块（保持单链 10 分钟，最大化 BTC 同构性）。

## 3. 威胁模型：我们在防谁

| 对手 | 能力 | 设计对策 | 预期压制效果 |
|---|---|---|---|
| **全定制 ASIC** | 数千万美元 NRE、先进制程、HBM/GDDR 采购 | 三层防御（§5） | ≤1.5–2x，且轮换毁掉回收期 |
| **FPGA** | 灵活但带宽弱（板载 DDR） | 带宽绑定 | ~0.1x，无威胁 |
| **CPU 大军** | 内存带宽是 GPU 的 1/5–1/20 | 带宽绑定 | ~0.02–0.1x，自动出局 |
| **AI 加速器 / AI 数据中心集群** | 10^4–10^5 卡集中算力、可短租 | 带宽经济学（§7.1；集群专项评估 §7.6） | $/hash 差 5–9x，无经济意义；启动期短租攻击见 R4 |
| **大规模 GPU 农场** | 直接买卡，无法用算法排除 | Stratum v2、准入低 | 属于分布性问题而非算法问题，见 §7.4 |
| **云 GPU 短租 51%** | 按小时租用 | 攻击成本分析（§7.4） | 链小的时候是真实风险，靠启动期防御 |

**关键认知**：链上无法"检测"硬件——哈希就是哈希。唯一武器是**经济学**：让攻击者/矿机厂商的成本函数最优解恰好是"买消费级显卡"。

## 4. 链层设计（BTC 同构部分）

原则：**除了 PoW 和区块头扩展字段，一切照抄 Bitcoin。** 差异点用表格管理，其余语义引用 Bitcoin 规范。

### 4.1 共识与经济参数

| 参数 | 值 | 与 BTC 关系 |
|---|---|---|
| 共识 | Nakamoto 最长链 | 相同 |
| 目标出块间隔 | 600 秒 | 相同 |
| 难度调整 | 每 2016 块，BTC 公式 | 相同 |
| 初始区块奖励 | 50 GTC | 相同 |
| 减半周期 | 210,000 块（~4 年） | 相同 |
| 总量上限 | 21,000,000 GTC | 相同 |
| Coinbase 成熟期 | 100 块 | 相同 |
| 区块重量上限 | 4,000,000 WU（segwit 风格 witness 折扣） | 相同 |
| 交易模型 | UTXO | 相同 |
| 签名 | secp256k1；**Schnorr（BIP340）为默认**，ECDSA 兼容（两者都收） | Taproot 语义 |
| 地址 | Bech32m，HRP = `gtc` | 格式同、前缀不同 |
| 脚本 | Bitcoin Script 子集（**含 CLTV/CSV 时间锁**，边界见 §4.5）+ Taproot 风格 v1 witness | 兼容移植 |
| Coinbase 数据 | 必须以算法版本标记开头（见 §6.6） | 扩展 |

### 4.2 区块头（128 字节，BTC 80 字节的超集）

```
偏移   长度   字段
0      4     version          (与 BTC 语义一致)
4      32    prev_hash
36     32    merkle_root
68     4     timestamp        (BIP113 median-time-past)
72     4     nBits            (难度目标，紧凑编码，与 BTC 相同)
76     8     nonce            (64-bit，防止非撞不可的回绕)
84     2     algo_version     (Geyser 版本号，见 §6.6)
86     32    mix_digest       (PoW 中间态摘要，用于轻客户端验证)
118    10    reserved         (0)
```

设计说明：

- `nonce` 扩到 8 字节：难度进入 2^64 空间后矿工不必频繁改 extranonce 回绕 coinbase；
- `mix_digest` 对应 Ethash 的 mixHash：轻客户端只需 48MiB cache（§6.2）即可验证区块头，无需下载 6GiB dataset；
- `algo_version` 是算法敏捷性的锚点：所有共识规则由它派生。

### 4.3 区块大小与吞吐

区块重量上限 **4,000,000 WU**，计算公式与 BIP141 完全相同：

```
weight = 3 × base_size + total_size
  base_size = 不含 witness 的序列化字节数
  total_size = 含 witness 的总字节数
  vsize     = ⌈weight / 4⌉          (费用估算用)
```

实际尺寸：

| 场景 | 大小 |
|---|---|
| 空区块 | ~250–400 B（128B header + coinbase） |
| 典型饱和区块 | 1.5–2 MB |
| 理论上限（全 witness 病态构造） | ~4 MB |

容量与吞吐（理论饱和值，600s 出块）：

- SegWit 典型 1-in-2-out（~566 WU/tx）：~7,000 tx/块 ≈ **12 TPS**
- Taproot keypath（~442 WU/tx）：~9,000 tx/块 ≈ **15 TPS**
- 日上限 ~1.0–1.3M tx；磁盘增长：饱和最坏 ~576 MB/天 ≈ **210 GB/年**（BTC 实际历史 ~60 GB/年）

**保持 4M WU（不扩）的理由**：

1. 本链定位价值存储，不是清算层——吞吐诉求本就不存在；
2. 区块越大，全节点门槛（IBD 时长/带宽/存储）越高，与"分布性最大化"的第一性直接冲突——不能一边用 Geyser 保矿工分布、一边用大区块毁节点分布；
3. 10 分钟出块下，4MB 传播是秒级延迟，孤块率影响可忽略，没有 segwit 时代那种"必须扩"的压力；
4. 需要更多吞吐的正解是 L2，不是加大基座。

数值上属 P0 可微调参数，但当前无变更动机。

### 4.4 有意保留的 BTC 缺陷/特性

- 难度调整 2016 块窗口的滞后问题：保留（同构优先）；若测试网暴露算力剧烈波动问题，v2 再议；
- 10 分钟出块导致吞吐低：保留。本链定位是价值存储 + 分发式安全，不是支付清算网。

### 4.5 脚本子集边界（已定稿，2026-08-29）

主干 = Taproot 风格 v1 tapscript（语义对齐 BIP341/342/343），opcode 采用白名单制，白名单外按 tapscript 语义处理（终止执行、判定失败）：

| 类别 | 启用的 opcode |
|---|---|
| 常量/压栈 | OP_0, OP_1–OP_16, 直接压栈, OP_PUSHDATA1/2/4 |
| 栈操作 | OP_DUP, OP_DROP, OP_IFDUP, OP_DEPTH, OP_SWAP, OP_OVER, OP_ROT, OP_NIP, OP_PICK, OP_ROLL, OP_SIZE |
| 控制流 | OP_IF, OP_NOTIF, OP_ELSE, OP_ENDIF, OP_VERIFY, OP_RETURN |
| 算术/比较 | OP_1ADD, OP_1SUB, OP_NEGATE, OP_ABS, OP_NOT, OP_ADD, OP_SUB, OP_BOOLAND, OP_BOOLOR, OP_NUMEQUAL(VERIFY), OP_NUMNOTEQUAL, OP_LESSTHAN, OP_GREATERTHAN, OP_LESSTHANOREQUAL, OP_GREATERTHANOREQUAL, OP_MIN, OP_MAX, OP_WITHIN |
| 密码学 | OP_RIPEMD160, OP_SHA256, OP_HASH160, OP_HASH256, OP_CHECKSIG(VERIFY), OP_CODESEPARATOR |
| **时间锁** | **OP_CHECKLOCKTIMEVERIFY (CLTV), OP_CHECKSEQUENCEVERIFY (CSV)** —— 启用，支持 HTLC、金库、延迟取款冷备份等场景 |
| 升级预留 | OP_SUCCESSx 机制保留（为 v2 软分叉留门，对齐 tapscript） |

明确禁用（及理由）：

- **OP_CHECKMULTISIG / CHECKMULTISIGVERIFY**：多签统一走 Schnorr key aggregation（MuSig2 风格）—— 聚合公钥 + 单条签名，更省空间，且不继承裸 multisig 的 off-by-one 历史包袱（对齐 BIP342 处理方式）；
- **OP_MUL / OP_DIV / OP_MOD**：历史禁用区，溢出语义需重新设计，v2 连同 64-bit 算术一起评估；
- **OP_CAT 等拼接类**：初期禁用，v2 视 Bitcoin 生态 OP_CAT 实践再评估。

签名哈希布局、资源限制（脚本体积、栈深、sigops 计数）在 P0 规范冻结时逐条对齐 BIP341/342。

### 4.6 数据载体与存证（Data anchoring）

**共识保持中立**：不设特殊"存证交易类型"，不在共识层做任何内容感知。理由：链上数据无法实质审查（witness 签名研磨可藏任意比特，这是数学事实不是漏洞）——与其假装能挡，不如像 BTC 一样把数据需求**收编到最无害的载体**。

**OP_RETURN 数据载体政策（mempool 标准性规则，非共识）**：

- 每笔交易允许 1 个 OP_RETURN 输出、负载 ≤ **80 字节**（对齐 BTC `MAX_OP_RETURN_RELAY`）；
- 80B 恰好容纳：32B 摘要 + 4B 协议标识 + 时间/批次/Merkle 路径等元数据，也**恰好兼容 OpenTimestamps 附件格式**（跨链锚定零额外设计）；
- OP_RETURN 输出不可花费 → **UTXO 零污染**。这是收编的核心收益：没有该政策时用户会把数据藏进假 P2PKH 地址输出，那才真正永久污染 UTXO 集；
- 80 是策略常量而非共识常量：节点可自行调整，未来无需硬分叉即可放宽。P0 冻结默认值 80。

**锚定架构（应用层模式，规范引导、不强制）**：

- 批量聚合：N 份证据哈希 → Merkle 树 → 根上链（OpenTimestamps 模式）。单份证据的验证只需根 + Merkle 路径，不必上链；
- 容量账：单笔裸锚定交易（1 P2TR 输入 + 1 个 80B OP_RETURN 输出）≈ 630–900 WU；饱和区块 4M WU → 理论裸锚 ~60–90 万笔/天；聚合后一笔交易可代表百万份证据，**实际上限是费用而非容量**；
- 时间证明：10 分钟块 + BIP113 MTP → "该数据于时刻 X 前已存在"的证明粒度为小时级，司法场景够用；
- 最终性指引：存证服务等 6 确认（与 BTC 惯例同），并监听链重组、重组后重发锚定。

**两条诚实边界**：

1. **公信力不是上链自带的**：司法实践认可区块链证据，但证据力随锚定链的公信力而异——新链弱于 BTC 是客观事实。正解是**双锚定**：日常/高频锚 GTC（便宜、自有生态、秒级确认），终局性锚定期同步锚 BTC（公信力背书）。GTC 载体格式与 OTS 兼容让这件事零成本；
2. **链上只放哈希**：原始文件永不进链——公开不可篡改账本 ≠ 存储位置。隐私、内容合规全部在链下解决（本地库/IPFS/联盟链），GTC 保持内容中立，不承担监管面。

**战略注脚**：存证/锚定是付费、UTXO 中性、与代币投机无关的**可持续费用需求**——在区块奖励趋零的远期，这类需求是安全预算的健康来源。基座不为应用层做特殊设计，但应用层会反哺链的安全。

## 5. 抗 ASIC 设计原理：三层防御

### 第一层：带宽绑定（Bandwidth-binding）—— 学 Ethash

每次哈希必须**随机访问**一个 GB 级数据集至少 64 次 × 128B = 8 KiB。瓶颈从"逻辑门翻转速度"（ASIC 的主场）转移到"显存带宽"（GPU 的主场）。

- ASIC 想赢就得堆 HBM/GDDR，而显存占 GPU BOM 的大头、也是全球紧缺商品——**矿机厂和游戏玩家在同一个市场里抢内存，抢不过规模经济**；
- 2026 年消费级 GPU 的 $/GB/s ≈ 0.8–1.2，是所有计算平台里带宽性价比最高的（§7.1 量化）。带宽绑定不挑封装：独显 GDDR 与 UMA 统一内存一视同仁（§7.5）。

### 第二层：程序化计算混合（Programmatic mix）—— 学 ProgPow/KawPow

每个区块的 PoW 程序由**上一个块的哈希**随机生成（256 条混合整数/浮点指令），全网所有矿工在同一段时间内执行**同一份随机程序**。想跑赢它，芯片必须实现：

- 完整的 INT32/INT64 ALU（乘法、旋转、位操作）；
- IEEE-754 精确语义的 FP32 单元；
- 通用寄存器堆 + 程序控制流；

—— 即：**必须造一个 GPU**。专用逻辑只能加速其中一小部分，剩下的面积还是 GPU 的面积。这就是 ProgPow 的核心洞见：*让算法的形状 = GPU 的形状，ASIC 就失去 specialize 的空间。*

### 第三层：算法演进（Agility）—— 学 Monero 的社会契约

1. **参数表硬编码在共识里**：数据集增速、指令配比、lane 数等由 `algo_version` 决定，版本时间表公开（§6.6）；
2. **常规轮换**：计划中每 ~2–3 年一次参数级升级（对 GPU 矿工 = 矿软件升级；对 ASIC = 流片作废）；
3. **应急预案**：若监测到 ASIC 效率 ≥3x（算力异常跳变 + 已知硬件逆向），社区执行应急轮换（预案草案随主网发布前就绪，避免临阵磨枪）。

Monero 用这招在 2018–2019 连续四次击退 ASIC，是**唯一被实战验证过**的社会契约防御。

### 为什么不用现成算法？

| 候选 | 不采用的原因 |
|---|---|
| Ethash | 已被逆向过（2–3x ASIC 出现过）；DAG 生成慢；无程序层 |
| KawPow (Ravencoin) | 可用，但无带宽增长政策、无版本敏捷框架，且我们想要非 Ethereum 生态参数 |
| RandomX | CPU 形状（分支 + AES + 大页），GPU 反而吃亏，与 G2 冲突 |
| Autolykos (Ergo) | 接近理想，但无程序层、无轮换设计 |
| SHA-3/BLAKE3 纯哈希 | 零内存依赖 → Kaspa 结局 |

Geyser = **Ethash 的内存核 + KawPow 的程序层 + Monero 的轮换契约 + 显式 VRAM 政策**。

## 6. Geyser PoW 算法规格（核心章节）

### 6.1 总览

一次哈希 = 32 个并行 lane（正好一个 CUDA warp / AMD wavefront 的一半）执行 64 轮循环：

- 每轮：**一次数据集随机访问**（全 lane 共享索引、各取不同字）+ **4 条随机程序指令**；
- 结束后所有 lane 状态折叠为 256-bit 输出，与难度目标比较。

```
hash_geyser(header, nonce, program, dataset) -> u256:
    seed_state = keccak512(header_128B || nonce)        # 64B
    for lane in 0..32:
        R[lane] = 64 × u32 寄存器, 由 seed_state 按 lane 派生
        F[lane] = 64 × f32 寄存器, R 的位重解释
    for round in 0..64:
        idx   = index(R[0][0..8], round) mod N_items    # 数据集索引,全 lane 共享
        item  = dataset[idx]                            # 128B = 32 × u32
        for lane in 0..32:
            R[lane][k] = fnv1a(R[lane][k], item[lane])  # 每条 lane 吃一个字
        execute program[round*4 .. round*4+3]           # 对所有 lane 执行同样 4 条指令
    mix = keccak256(concat_lane_states(R, F))           # 折叠
    return mix                                          # mix 同时写入 header.mix_digest
```

每 nonce 的数据集随机读总量：64 轮 × 128B = **8 KiB**。以 RTX 5090（1.79TB/s）估算理论上限 ~220 Mh/s，实际（含缓存效应 + ALU 负载）约 60–120 Mh/s —— 与 Ethash 时代同数量级，证明带宽确实是瓶颈而非逻辑。

### 6.2 Epoch 数据集（两级结构）

两级结构（学 Ethash）是"**挖矿需要 6GiB，验证只需 48MiB**"的关键：

```
epoch_seed(0) = keccak256("GTC/mainnet/genesis-seed-v1")
epoch_seed(e) = keccak256(epoch_seed(e-1))             # 种子链,由高度唯一决定

cache(e)       = gen_cache(epoch_seed(e))              # 48 MiB, 内存硬化 KDF (Argon2id 风格, 顺序依赖)
dataset(e)[i]  = gen_item(cache(e), i)                 # 每项 64 轮混合,项间独立可并行
```

- **cache（48MiB）**：轻客户端与全节点验证时持有，逐项重生成被访问的 dataset 项；
- **dataset（6GiB 起步）**：矿工全量持有（放显存；显存不足时放内存也能跑，只是更慢）；
- **UMA 机器（Apple Silicon / Strix Halo 等）**：dataset 直接驻留统一内存，GPU 零拷贝随机访问，不存在"显存装不下退到 PCIe"的惩罚路径——UMA 是 dataset 驻留的天然最优形态（详见 §7.5）。最小内存建议 16GB（dataset 6GiB + OS 余量）；
- 验证一个区块头：重生成 64 个 dataset 项 ≈ 64 × ~130µs ≈ **8ms CPU**（满足 G4）；
- Epoch 边界由矿工提前 1024 块开始预生成，p2p 分发 dataset 文件（经验来自以太坊 DAG 分发，无新风险）。

### 6.3 容量政策（VRAM 政策）—— 显式写进共识

| 项 | 值 | 理由 |
|---|---|---|
| 初始 dataset | 6 GiB | 2026 年入门矿卡（8GB）可容纳（6 + ~1.3GB 余量） |
| 每 epoch 增长 | +32 MiB | ≈ +0.83 GiB/年 |
| Epoch 长度 | 2016 块（与难度窗口对齐，~14 天） | 心智模型简单 |
| 2030 年规模 | ~9.3 GiB | 同期主流卡 16–24GB |
| 2036 年规模 | ~14.4 GiB | 同期主流卡预计 32GB |

**政策声明**：dataset 目标规模 ≤ 同期**中位数游戏显卡 VRAM** 与**中位数 UMA 机器内存**两条曲线各自 60% 的较小值（2026 年参照：独显中位 ~16GB / UMA 中位 ~24GB，约束实际取独显侧）。该比例每两年复核一次，若市面 VRAM 增长停滞，通过 `algo_version` 升级冻结/放缓增长（对 GPU = 矿软件更新）。增长的意义：持续抬高 ASIC 的内存 BOM 下限（Bitmain E3 就是被 4GB 上限物理报废的）。

### 6.4 程序层（每块变化的随机程序）

```
program_seed = keccak256(prev_block_hash || epoch_seed)
rng          = xorshift128+(program_seed)
program      = 256 条指令, 由 rng 生成:
               - dest  ∈ [8, 64)     # 前 8 个寄存器是 mix 态,禁写
               - src1  ∈ [0, 64)
               - src2  ∈ [0, 64) 或立即数
               - opcode ∈ 指令集
               - 每 8 条插入 1 条 FP 指令(固定模式,保证 FP 占比)
最后 32 条为 merge 指令: F 寄存器位重解释后乘法混合回 R
```

**指令集（v1，18 整数 + 3 浮点）**：

| 类别 | 指令 |
|---|---|
| 算术 | iadd, isub, imul (u32), imulhi (u32 高位), umin, umax |
| 位运算 | and, or, xor, andnot, shl, shr, rol, ror |
| 位统计 | popcount, clz, bswap, brev |
| 混合 | fnv1a-mul |
| 浮点 | fadd, fmul, fma (均为 IEEE-754 f32, round-to-nearest-even) |

**确定性红线（FP 是历史坑点，KawPow 踩过）**：

1. **禁止**超越函数（sin/exp/…）、除法、开方——跨平台位不一致；
2. **FMA 是允许的**：IEEE-754 对 fma 的定义是无限精度乘加后单次舍入，所有合规硬件位一致；
3. **Denormal 必须显式处理**：GPU 默认 FTZ、CPU 默认不 FTZ。参考实现规定每条 FP 指令后跟显式 `if (|x| < 2^-126) x = 0`（一条 compare+select，成本可忽略），语义在所有平台严格一致；
4. 必须发布 **NVIDIA / AMD / Intel / x86 CPU 四方交叉验证的测试向量集**（每 algo_version 一套，含 ≥10^6 随机程序-状态对），这是 Phase 0 的验收标准。

**CUDA/ROCm 编译纪律**：禁用 `--use_fast_math` / `-ffast-math`；nvcc 显式 `--ftz=false`（语义已在算法层自洽，编译器旗标只作双保险）。

### 6.5 难度与目标

与 BTC 完全一致：`nBits` 紧凑编码 256-bit 目标，`mix ≤ target` 即有效。难度公式、2016 块调整窗口、调整幅度 ±4x 限制均照抄，不赘述。

### 6.6 算法版本与演进时间表

`algo_version`（header 偏移 84）决定全部算法参数：

| 版本 | 计划高度 | 变更内容 |
|---|---|---|
| 0x0001 | 创世 | Geyser v1 规范冻结 |
| 0x0002 | ~第 3 年 | 指令集扩展（增加 4–6 条）、FP 配比调整 |
| 0x0003 | ~第 6 年 | 视 VRAM 市况调整增长政策；lane 结构重排 |
| 0xFFxx | 应急 | 预案版本，参数未公开但规范预置于客户端 |

规则：

- 版本升级 = **共识内建的预定硬分叉**（高度表在创世块里公开），所有客户端预置后续版本实现；
- **轮换成本的不对称性是防御本身**：GPU 矿工升级 = 下载新矿软件（0 成本）；ASIC = 一轮流片 + NRE 重付。计划轮换间隔 < ASIC 回本周期（经验值 ~18–24 个月），使投资理性上不成立。

**结论：消费级 GPU 是全宇宙带宽性价比最高的平台。** Geyser 让单位算力 ≈ 正比于带宽，就等于把挖矿的最优解锁定在游戏显卡上。CPU、FPGA、AI 加速器在 $/hash 上被结构性排除。

注意 $/GB/s 只是必要条件——还需有能"喂饱"带宽的并行计算单元：UMA SoC 内置完整 GPU，上表 UMA 行是**可兑现**的算力；桌面/服务器 CPU 为随机访问延迟所限，只能跑出峰值带宽的一小部分，CPU 行实为高估。

### 7.2 定制 ASIC 的最优情形推演

假设厂商完美实现 Geyser 专用芯片：

| 成本项 | ASIC | 消费 GPU |
|---|---|---|
| 内存 | 必须买 GDDR6/6X（和显卡厂抢同一货源） | 显卡自带 |
| 逻辑 | 去掉显示/光追冗余，省 ~30% die | 全功能 die |
| 板级/电源/散热 | 自建 | 厂商规模摊薄 |
| NRE | $10–30M，需摊入售价 | $0（NVIDIA 摊到游戏市场） |
| 产量 | 数万–数十万片 | 数千万片/年 |

最好情形下 ASIC BOM 便宜 ~25–35%，但 NRE 摊销与产量劣势吃掉大部分；加上 §6.6 的 2–3 年强制轮换（芯片在回本前作废），**理性厂商不投**。Ethash ASIC 实测优势 ~2–3x 是本估算的历史校准点——Geyser 比它多了程序层与轮换，只会更低。

### 7.3 各平台预期挖矿效率（相对 5070-class = 1.0）

|---|---|---|
| 消费 GPU（8GB+） | 1.0 | 唯一合理选择 ✓ |

| FPGA | ~10x 差 | 出局 |

### 7.4 诚实的风险账：GPU 侧的中心化

1. **GPU 农场**：无法用算法排除（卡就是卡）。缓解：准入极低（一张卡就能挖）+ Stratum v2 让小矿工不经中心化池代理选块权；
2. **51% 攻击成本 = 折旧 + 电费**：因为攻击完的卡能以 ~70% 残值卖回游戏市场。这是商品硬件的固有代价——但对称地看，BTC 的 ASIC 二手残值≈0，其"高退出成本"同时也是矿工被绑定的中心化力量。两害相权，取分散；
3. **启动期最脆弱**：全网算力小于一个 GPU 云集群时，短租攻击可行。对策见 §9（激励测试网 + 启动期 checkpoint 广播）。

### 7.5 统一内存架构（UMA）影响评估（2026-08-29 新增）

Apple Silicon（M 系列）、AMD Strix Halo、Snapdragon X 等 SoC 让 CPU/GPU 共享同一内存池。若 UMA 未来成为个人电脑主流形态，对本设计的影响：

**共识层：零改动。**

1. **抗 ASIC 论证不变**：Geyser 绑定的是"内存带宽"这个物理量，不是"独立显存"这种封装。ASIC 推演（§7.2）本就假设厂商自购商品内存（GDDR 或 LPDDR 皆同）——UMA 化只是让消费设备也长成"SoC + 大内存"的样子，攻防双方的武器没有变化；程序层与轮换契约照旧成立；
2. **验证路径无关**：cache 验证是纯 CPU 工作，与内存形态无关。

**实现与政策层：三处跟进。**

1. **矿工基本面变宽（利好分布性）**：UMA 机器免 VRAM 拷贝，dataset 驻留统一内存即被 GPU 直接随机访问。粗算：M4 Max（546GB/s）理论 ~67 Mh/s、实际 ~30–40 Mh/s，**约为一张 RTX 5070 的八成**；M3 Ultra（819GB/s）可达 4080-class。LPDDR 能效还略优（M4 Max Studio 整机 ~0.26 W/(GB/s) vs 5070 整机 ~0.42）——**每 hash 电耗 UMA 反而更低**，高电价地区 UMA 是理性矿机。"已经拥有的 Mac/UMA 迷你机"边际成本只剩电费，这类沉没成本算力与"闲置游戏 PC"同一逻辑，是分布性的净增量；
2. **不会形成新集中点**：整机 $/GB/s 仍是独显的 4.5–8x 差（§7.1 表），UMA 撑不起算力主导地位；高二手残值特性也使其自然落入 §7.4 既有的攻击成本框架，无需新分析；
3. **工程成本：第三个 GPU 后端**：Apple 走 Metal（Apple GPU 的 SIMD-group 恰好也是 32，lane 结构零改动），测试向量平台由四方扩为五方（+Apple GPU 与 ARM64 CPU）。好消息是 FP 确定性红线已预先覆盖 Apple：Apple GPU 属 denormal-FTZ 阵营，§6.4 红线 #3（每条 FP 指令后显式清 denormal）恰好使 FTZ 差异无害化；Metal 侧只需保持 fast-math 关闭（MSL 默认即精确数学）。

**若 UMA 真成主流（2028+ 情景）**：miner 基数从"装独显的电脑"扩大为"任何现代电脑"——更接近中本聪"人人电脑挖矿"的原初理想，同时保留 GPU 级带宽经济学。§6.3 容量政策已按"独显 VRAM / UMA 内存"两条中位曲线的较小值取约束，UMA 化不会令 dataset 增长失控。

**新增工程注意**（非协议风险）：笔记本 UMA 满载散热受限（Air 不适合，Studio/mini/Pro 合理）；macOS 内存压力换页会悄悄吃掉算力，矿工需监测 memory pressure 并优雅降速。

### 7.6 AI 数据中心与租用算力威胁评估（2026-08-29 新增）

2026 年的 AI 训练/推理集群（H100/H200/B200，单集群 10^4–10^5 卡）是地球上最集中的算力池。诚实声明在前：**AI 加速器是通用计算硬件，跑 Geyser 的程序层零折扣、6 GiB dataset 轻松装进 HBM——架构上没有任何东西拦得住它。防线纯粹是经济性的。** 因此必须把账算清楚。三个问题拆开：

**Q1：AI 集群挖 GTC 划算吗？—— 不划算，结构性 5–9x 劣势**

| 平台 | 带宽 | 参考价 | $/GB/s | 相对 5070 |
|---|---|---|---|---|
| H100 SXM | 3.35 TB/s | ~$25,000 | ~7.5 | 9x 差 |
| H200 | 4.8 TB/s | ~$32,000 | ~6.7 | 8x 差 |
| B200 | 8 TB/s | ~$40,000 | ~5.0 | 6x 差 |
| RTX 5070（基准） | 672 GB/s | $550 | ~0.82 | 1x |

这个差距是**代际稳定的**：H100 vs 4090 = 4.7x，B200 vs 5090 = 4.4x——因为 AI 卡和游戏卡骑的是同一代内存技术，HBM 的溢价 = 数据中心利润率 + 先进封装成本，不是暂时技术差。租用口径更惨：H100 spot $2.5–3.5/hr 提供约 5 张 5070 的算力，但成本是 5070（摊销+电费 ~$0.06/hr）的 50 倍——**租 AI 卡挖矿每 hash 亏 ~10x**。

**Q2：短租 AI 集群打 51%？—— 启动期真实（R4 已登记），但攻击者支付"AI 溢价"**

- 算例：早期网络 5 万张消费卡（≈2 Ph/s），51% 需 ~1 万张 H100 ≈ **$30k/小时**；
- 攻击者为每 hash 支付的成本是诚实矿工的 5–10x（AI 溢价）——网络越大，这笔账越荒谬；攻击成本随全网算力线性增长，而全球 cloud spot 深度不会；
- 现实摩擦：spot 容量分散在 AWS/GCP/Azure/CoreWeave/Lambda/Oracle 等多家，短时间扫货 1 万张会推高公开 spot 价格（**本身就是可见的预警信号**），provisioning 以小时/天计；
- 不对称性在防守方：攻击需要**持续** 51%，防御只需守住主链；诚实方同样可以租卡应急；
- 游戏论兜底与 BTC 相同：掌握巨量算力的实体，诚实挖矿收益 > 攻击收益——攻击摧毁的是自己正在挖的币的价值；新币流动性薄，做空获利空间同样有限。

**Q3：AI 冬天 + 大规模闲置机队？—— 唯一真正需要长期盯的情景**

若 AI 需求崩塌留下闲置机队，其边际成本只剩电费（H100 整卡 ~1kW ≈ $0.10/hr），每 hash 成本反而低于 5070。此时威胁不是"来挖矿"（挖矿是贡献安全），而是**单一实体算力集中 >50%**：

- 机会成本闸门：只要 AI 负载时薪 > 挖矿时薪（历史关系 10–20x），理性机队不来；会来的前提是 AI 死了或链价高到荒谬——前者是宏观黑天鹅，后者说明网络已经成功；
- 若真发生：性质等同 R5 的 GPU 农场集中，但实体更少、算力切换更快。缓解属运营层：池级算力集中度监测、异常跳变告警、必要时启动应急 checkpoint 社会共识——写进 P2 公测的运维手册。

**结论**：AI 集群是"最贵的算力"，不是"最强的敌人"。Geyser 的经济防线对它成立——它甚至是被排除得最干净的平台（$/GB/s 最差情形仍差 5x）。登记在案的风险维持两条：R4（启动期短租攻击，高，随网络增长衰减）与 R8（AI 宏观周期，新增闲置机队情景）。

## 8. 挖矿经济学（示例框架）

不做价格预测，只给估算框架：

- 出块：144 块/天；首年日增发 = 144 × 50 = 7,200 GTC/天；
- 假设全网 100 万张 5070-class（每张 ~40 Mh/s）→ 全网 40,000 Mh/s 量级；单卡日收益 = 日增发价值 / 全网算力份额——**代币价值决定全网算力规模，而非反过来**；
- 电费门槛示例：5070 挖 Geyser 满载 ~200W；若代币价格使单卡日收益 < 电费，算力自然收缩到边际电价以下——与 BTC 相同的均衡逻辑，不重复发明。

## 9. 公平启动与治理

| 项 | 决定（v0.1 建议） |
|---|---|
| 预挖 | **0**。无 premine、无 instamine |
| 开发资金 | 不写进共识（无 dev tax）。生态靠捐赠/基金，保持与 BTC 同构的纯粹性；若社区后续投票要开发税，走 algo_version 之外的分叉流程 |
| 创世分发 | 公开规范 + 三平台客户端二进制 + 6 个月以上公开测试网，之后约定 UTC 时刻启动 |
| 启动期防御 | 前 10,000 块由官方渠道发布签名 checkpoint，防早期私有链延展 |
| 挖矿协议 | **Stratum v2**（参考实现内建）：小矿工保留选块权，削弱中心化池 |
| 算法治理 | 参数变更 = algo_version 预定硬分叉（§6.6），核心规范用 BIP 式流程，多客户端实现制衡 |

## 11. 风险登记册（诚实清单）

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | 3 年内出现 ≥3x ASIC | 中 | 应急轮换预案 + 算力异常监测（难度/单位功耗跳变） |
| R2 | FP 确定性跨平台 bug（KawPow 曾踩） | 中 | §6.4 红线 + P0 四方测试向量是硬验收门槛 |
| R3 | VRAM 市场停滞，dataset 增长把矿工挤出去 | 低-中 | §6.3 显式政策，可冻结增长 |
| R4 | 启动期云 GPU / AI 集群短租 51% 攻击 | 高（链小时期，随全网算力增长衰减） | checkpoint 广播 + 激励测试网拉高初始算力；攻击成本算例与 spot 预警信号见 §7.6 |
| R5 | GPU 农场算力占比过高 | 中 | Stratum v2；接受为分布性代价（优于 ASIC 集中） |
| R6 | 算法轮换执行时社区分裂 | 低 | 高度表创世即定，轮换是共识内建而非临时决定 |
| R7 | dataset 分发在 epoch 边界造成孤块 | 低 | 提前 1024 块预生成 + p2p 分发（以太坊已验证） |
| R8 | AI 宏观周期双向影响：繁荣期吸走显卡供给与二手卡源；衰退期闲置 AI 机队成为高集中度算力来源 | 低-中 | 机会成本闸门 + 池级集中度监测（§7.6 Q3）；运维手册进 P2 |
| R9 | UMA 主流化扩大 miner 软件维护面（Metal/Vulkan 后端成本） | 低 | 后端接口抽象统一；Apple/Metal 进 P2 非关键路径 |
| R10 | UMA 机器上散热/内存换页拖垮矿工体验 | 低 | 矿工侧工程（pressure 监测 + 降速），非协议风险 |
| R11 | 数据嵌入滥用（witness 塞大 payload、垃圾锚定挤占区块） | 低 | 共识中立 + OP_RETURN 80B 标准化收编（UTXO 零污染）+ 费用市场定价；扩容诉求走 L2 |
